# SNSコンテンツ管理システム

## 概要
地方フルリモートエンジニアとしての日常・リアルを、X / Threads / Instagram / TikTok / note の5媒体で発信するためのコンテンツ管理システムです。

発信コンセプトは「地方フルリモートエンジニアの日常・リアルを発信し、その生活に憧れを感じてもらうこと」。最終的にはnoteや直接問い合わせへ、営業感なく自然に読者を導くことを目指します。

## ディレクトリ構成

```
sns-manager/
├── prompts/            # 運用の各ステップに対応したプロンプト
│   ├── 01_record.md    # 投稿を記録する
│   ├── 02_collect.md   # 他アカウントのバズ投稿を収集する
│   ├── 03_analyze.md   # 実績とバズ傾向を分析し、次回方針を決める
│   └── 04_generate.md  # 分析結果とスキルをもとに投稿文を生成する
├── skills/              # 各媒体ごとの投稿ルール・型・トーンを定義
│   ├── x.md
│   ├── threads.md
│   ├── instagram.md
│   ├── tiktok.md
│   └── note.md
├── data/
│   ├── posts/           # 媒体ごとの投稿記録（実績データ、300行ごとにファイル分割）
│   │   ├── x/
│   │   │   ├── index.json
│   │   │   └── x_2026_001.json
│   │   ├── threads/
│   │   │   ├── index.json
│   │   │   └── threads_2026_001.json
│   │   ├── instagram/
│   │   │   ├── index.json
│   │   │   └── instagram_2026_001.json
│   │   └── tiktok/
│   │       ├── index.json
│   │       └── tiktok_2026_001.json
│   ├── buzz/             # 他アカウントの伸びている投稿の収集データ
│   │   ├── index.json
│   │   └── buzz_2026_001.json
│   ├── analysis/         # 実績分析・次回投稿方針の記録
```

### `prompts/`
このシステムの運用フロー（生成 → 投稿 → 記録 → 収集 → 分析 → 生成…）を実行するためのプロンプト集です。各ファイルの役割・手順の詳細は `workflow.md` を参照してください。

### `skills/`
各SNS媒体の特性（文字数、トーン、投稿の型、アルゴリズム特性、NGパターンなど）をまとめたガイドラインです。投稿文を作成する際（`04_generate.md`）は、対象媒体の該当ファイルを参照してルールに沿った内容を作成してください。

### `data/profile.json`
発信者のプロフィールと発信コンセプトを保持する設定ファイルです。投稿内容がコンセプトからブレていないかを確認する際の基準になります。

### `data/posts/<platform>/`
媒体ごとに投稿を記録するデータです。1ファイルあたり最大300行で、超えた場合は連番ファイルを新規作成します（例：`x_2026_001.json` → `x_2026_002.json`、年をまたぐと `x_2027_001.json`）。`index.json` は各フォルダの目次役で、全ファイルの一覧とサマリー（`overall_summary`）を保持します。読み込み時はまず `index.json` だけを読み、必要なファイルのみ追加で開く運用を想定しています。

各投稿のスキーマ：
```json
{
  "id": "20260811-001",
  "date": "YYYY-MM-DD",
  "theme": "投稿のテーマ",
  "text": "投稿本文",
  "type": "気づき型 | リアル日常型 | 問いかけ型",
  "hook": "フックの構造メモ",
  "status": "投稿済み | 未投稿 | 見送り",
  "reaction": {
    "likes": 0,
    "reposts": 0,
    "replies": 0,
    "bookmarks": 0
  },
  "rating": "良かった | 普通 | 微妙",
  "memo": "振り返りメモ"
}
```

### `data/buzz/`
X / Threads などで伸びている他アカウントの投稿を収集した参考データです。自分の投稿の型・フックづくりの参考にします（模倣・転載目的ではありません）。`posts/` と同様、300行ごとにファイル分割し `index.json` で管理します。

### `data/analysis/`
`data/posts/` の実績と `data/buzz/` の傾向を突き合わせた分析結果です。良かったパターン・悪かったパターン・次回投稿方針（`todays_policy`）を記録し、`04_generate.md` の入力として使います。

### `drafts/`
投稿前のアイデアや下書きを一時的に置いておく場所です。清書・投稿後は下書きを削除し、`data/posts/<platform>/` へ記録として移管してください。

## 使い方
基本的な運用サイクルは `workflow.md` を参照してください。概略は以下の通りです。

1. `04_generate.md` に沿って投稿文を生成し、`drafts/` に下書きを保存する。
2. 内容を確定させ、実際に投稿する。
3. `01_record.md` に沿って `data/posts/<platform>/` に記録する。
4. `02_collect.md` に沿って他アカウントのバズ投稿を `data/buzz/` に収集する。
5. `03_analyze.md` に沿って実績とバズ傾向を分析し、`data/analysis/` に次回方針を記録する。
6. 1に戻る。

## ファイル分割ルール（重要）
- 1ファイルあたり最大300行まで。超えたら新しいファイルを自動作成する。
- ファイル名は `プラットフォーム_年_連番.json`（例：`x_2026_001.json`）。
- 年をまたいだら連番をリセットする（例：`x_2027_001.json`）。
- 各フォルダの `index.json` には、全ファイルの目次・期間・サマリーを持たせ、生データを全部読まなくてもサマリーで8割の分析ができるようにする。
- 詳細な自動管理手順は `workflow.md` の「ファイル分割の自動管理ルール」を参照。
