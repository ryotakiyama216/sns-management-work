# ワークフロー

`prompts/` の4つのプロンプトは、以下のサイクルで運用する。

```
   ┌──────────────────────────────────────────────┐
   │                                                │
   ▼                                                │
04_generate（生成）── 投稿 ──▶ 01_record（記録）      │
   ▲                              │                 │
   │                              ▼                 │
   └──────── 03_analyze（分析）◀── 02_collect（収集）  │
                    │                                │
                    └────────────────────────────────┘
```

1. **04_generate.md（生成）**
   `skills/` のルールと、直近の `data/analysis/` の方針（`todays_policy`）をもとに投稿文を作る。下書きは `drafts/` に置く。
2. **投稿**
   確定した内容を実際にX/Threads/Instagram/TikTokへ投稿する（noteはここでは別運用）。
3. **01_record.md（記録）**
   投稿した（または見送った）内容を `data/posts/<platform>/` に記録する。一定期間後、同じプロンプトで実績（reaction）を更新する。
4. **02_collect.md（収集）**
   並行して、他アカウントの伸びている投稿を `data/buzz/` に収集する。
5. **03_analyze.md（分析）**
   `data/posts/` の実績サマリーと `data/buzz/` のパターンを突き合わせ、良かった点・悪かった点・次回方針を `data/analysis/` にまとめる。
6. 1に戻る。次回の `04_generate.md` はこの分析結果を参照する。

## 設計思想（なぜindex.jsonがあるのか）
- `data/` 配下の各フォルダは「1ファイル最大300行」で分割され、`index.json` がその目次役を担う。
- Claude Codeはまず `index.json`（サマリー情報のみ）を読み、必要な場合だけ個別ファイルを追加で読む。
- これにより、投稿数・収集数が増えても生データを全件読み込む必要がなく、分析の8割は `index.json` のサマリーだけで完結する設計になっている。
- ファイルの新規作成・連番管理・`index.json` の更新は、`01_record.md` / `02_collect.md` / `03_analyze.md` が実行時に自動で行う（「ファイル分割の自動管理ルール」参照）。

## ファイル分割の自動管理ルール
各記録系プロンプト（01 / 02 / 03）の実行時に、以下を必ずチェックする。
1. 対象フォルダの最新データファイルの行数（`file_info.count`）を確認する。
2. 300行を超えていた場合、新しいファイルを作成する（連番+1）。
3. 年をまたいでいた場合は連番を001にリセットする（例：`x_2026_001.json` → `x_2027_001.json`）。
4. 新しいファイルには `file_info` を設定してからデータを追記する。
5. 対象フォルダの `index.json`（`files` / 集計値 / `last_updated`）を更新する。
